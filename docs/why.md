# 为什么做 pdfmend：从搜索词倒推的痛点

调研时间：2026-11-17。方法：百度下拉词（真实输入）→ 平台内容验证 → GitHub issue 计数。
所有结论都可以被下面的原始证据推翻，欢迎拿反例来打。

## 1. 搜索词说了什么

百度下拉（`suggestion.baidu.com`，2026-11-17 抓取）：

| 种子词 | 高价值下拉 |
|---|---|
| pdf转excel | **pdf转excel表格错乱怎么办**、pdf转excel最简单方法、pdf转excel在线 |
| pdf转word | **pdf转word以后格式乱了**、pdf转word最简单方法 |
| pdf表格 | pdf表格怎么转换成excel表格、**pdf表格数据怎么复制到excel**、**pdf提取表格修改后怎么放回去** |
| 扫描件转 | 扫描件转换成excel表格、扫描件转换成word文档 |
| markdown | markdown转word、markdown转pdf工具、markdown转ppt |
| wps转 | wps转excel、wps转word怎么转换 |

三个可以直接读出来的事实：

1. **用户不是嫌慢、嫌贵，是嫌“转完是乱的”。** “错乱”“格式乱了”是下拉词里唯一带情绪的表述。
2. **“免费”出现频率极高**（pdf转excel免费转换器/免费版/在线），C 端付费意愿弱。
3. **“修改后怎么放回去”** 是个没人做的需求：用户要的不是一次性提取，是提取→改→回填的闭环。

## 2. 平台上的原话

- 知乎：「PDF 转 Excel 怎么弄都是乱的？因为 PDF 里没有表格」（文章标题本身就是结论）
- 知乎：「怎么免费地把pdf转换成excel？」51 赞，回答全是工具清单
- 小红书：「😭PDF转Excel总格式错乱」2026-11-15 发布，两天前
- 小红书：「15步搞定PDF转Excel！再也不用手动敲字」215 赞 —— 15 步，说明现有工具没解决
- 小红书：「银行流水PDF转Excel，对账3步搞定」—— 垂直场景已经有人在教

## 3. 开发者侧：GitHub 的数字

markitdown（195,786 star，MIT）：

- 321 个 open issue，其中 **272 个提到 table**
- 28 个提到 chinese，34 个提到 scanned
- #293「Tables in pdf files are not converted properly」2025-01 开到现在还开着
- #111「pdf转换中文内容报错」：Windows GBK 控制台直接崩

结论：**表格塌成单列**不是个别 bug，是这个工具架构决定的（PDF 转换器就是一层 pdfminer 调用，没有表格结构）。

## 4. 钱在哪里

CloudConvert 转一份 PDF→Excel 收 4 credits ≈ **$0.04**。
PDFXLSX 同样的活收 **$1/份**，贵 25 倍，卖点只有一句：“转出来不用再修”。

**25 倍差价不在转换代码，在“返工成本”。** 所以付费点不是“转换”，是“不用改”。

## 5. 空白位（这个 demo 要占的位置）

| 现有工具 | 缺什么 |
|---|---|
| markitdown | 表格塌、扫描件静默返回空、不告诉你坏了 |
| docling | 重、慢、英文优先、中文复杂版式要调 |
| 在线免费站 | 隐私、限额、要上传到别人服务器 |
| WPS/Adobe | 收费、桌面、批处理弱 |

没人做的一件事：**承认自己可能错，并标出哪里错。**

所以 pdfmend 的第一版只做三件事：

1. 表格优先：PDF 的表格要么进 Markdown，要么进 Excel，不塌成一段话。
2. 质量报告：每张表给置信度，扫描页、乱码页、跨页表明确标出来。
3. 本地运行：文件不出机器，`pip install` 就能跑。

不做 OCR（v0.1 明确不支持，检测到就报出来），不做回填，不做 SaaS。
先把“可信”这件事做出来，再谈别的。

## 6. v0.2：为什么转向“非标 PDF”

v0.1 发出去之后，判断变了一次：**通用转换不该和大模型竞争。** 版式规整的文件，ChatGPT / Claude / WPS AI 已经转得够好，而且会越来越便宜；用户换工具的成本却很低。

真正留着没人做、也没人愿意做的是**版面坏掉的 PDF**：

- 表格只有空格、没有框线（扫描后 OCR 过的报表、银行导出的流水）；
- 双栏 / 多栏排版，复制出来两句夹在一起；
- 每页重复的页眉页脚，被当成正文混进表格第一列；
- 一张表被切到两页，表头还重复一遍。

这四类恰好是大模型不稳定、规则代码能算准的地方 —— 全是几何，本地、可解释、可回归测试。所以 v0.2 把版面重建（`src/pdfmend/layout.py`）做成核心，通用转换维持“能用就行”。

边界仍然写清楚：竖排文字、印章盖字、手写批注处理不了，这类会报出来，不猜。
